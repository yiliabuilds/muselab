# 工作流：三条出图路线

入口：任何"出图"请求。**先选路线，再谈提示词。** 同一个设计走错路线，后果不是"不好看"，而是**把不存在的东西当成商品**。

三条路线按"能不能保证这是这件商品"排序：

| | A. Product Compositing | B. Creative Generation | C. Reference-Based Generation |
|---|---|---|---|
| 一句话 | 用真实商品像素换背景 | 把想法画出来 | 拿参考图让模型"重画一遍" |
| 生成模型 | **不用** | 用 ImageGen | 用 ImageGen |
| 商品像素 | 原样搬运，可逐像素校验 | 不存在（无实物或不用实物） | 被模型重绘，**无法逐像素校验** |
| 珠数/结构 | 与照片完全一致 | 按档案新画 | 大概率接近，可能被改 |
| 能否承诺"就是这件商品" | **可以**（在蒙版质量合格前提下） | 不能 | **不能**，只能标"模拟展示" |
| 典型用途 | 商品主图、详情页换背景、白底图 | 概念图、氛围图、系列合影 | 拍摄条件差但需要"更好看"的展示图 |
| 成本 | 0 额度 | 5–10 点/张 | 5–10 点/张 |
| 验收手段 | `pixel_integrity.py` + `mask_audit.py` | 视觉评分 + 可制作性 | 视觉核对 + 色差分层（不可承诺精确） |

**口诀**：有实物照片且要展示这件商品 → **A**；没有实物、只要气质 → **B**；有实物但拍得太差、非要模型美化 → **C，并且必须标注"AI 模拟"**。

旧版本文档里的 "Concept Mode / Product Fidelity Mode" 已废弃，映射关系：
- Concept Mode → **B. Creative Generation**
- Product Fidelity Mode → 拆成 **A**（能保真）与 **C**（不能保真但常用于救图）
  上一版把"参考图生成"叫作 strict fidelity，是**命名错误**：它实际是 C。

---

## A. Product Compositing（唯一可以承诺商品保真的路线）

### 使用条件

必须同时满足：

1. 有真实商品照片，商品在画面内**可见**；
2. 需求只是换背景 / 换底色 / 统一画布，**不需要改变商品本身**（不改结构、不改光位、不补画外）；
3. 原始照片的商品区域足够大、不过曝、不过虚（否则蒙版会碎）。

**不满足时的降级**：
- 需要改变商品本身 → 走 C，并降级为"模拟展示"；
- 商品只有 1/3 在画面里，需要"完整商品图" → **拒绝**，先补拍。补画外内容不是合成，是编造。

### 输入要求

| 必须 | 说明 |
|---|---|
| 原始照片 | 实拍原图，**不得**用上轮生成图代替（生成图已被重绘，像素无保真价值） |
| 抠图 | `cutout.py` 产出真 alpha PNG；`--instance N` 处理多主体 |
| 目标背景 | 明确色值（如 `#D6D6D6`）、`white`、`transparent` 或背景图 |
| 画布策略 | **`--keep-frame`**：保留原画布与 1:1 像素坐标，画外关系不变 |

### 执行流程

```bash
# 1. 抠图（真 alpha，不改 RGB）
python3 scripts/cutout.py source.jpg --out cutout.png --json cutout.json

# 2. 蒙版质检（不是可选项）
python3 scripts/mask_audit.py --image source.jpg --cutout cutout.png --json audit.json --overlay qa_mask.png

# 3. 合成（keep-frame：不裁 bbox、不缩放、不居中）
python3 scripts/compose.py cutout.png --out composed.png --bg '#D6D6D6' --keep-frame --json compose.json

# 4. 像素完整性（商品有没有被改）
python3 scripts/pixel_integrity.py --original source.jpg --cutout cutout.png \
    --composite composed.png --placement compose.json --bg '#D6D6D6' --json integrity.json

# 5. 登记任务（is_generative=false）
python3 scripts/muselab_state.py task-add ... --file task.json
```

**顺序不能反**：先合成再质检，会把"蒙版有洞"误认为"合成本身有问题"。

### 验收标准

**硬门禁**

- [ ] `pixel_integrity` 的 `cutout_vs_original` 为 0 差异（抠图没有重绘商品）
- [ ] `pixel_integrity` 的 `composite_vs_ideal_blend` 为 0 差异（合成没有偷偷调色/打光）
- [ ] `clipped_pixels == 0`（没有商品被画布切掉）
- [ ] `silhouette_components` 与抠图一致（没有整块结构消失）
- [ ] 目标背景实测色差 ≤ 1 LSB（纯色时）
- [ ] 原图的出画关系保持不变（左/底仍出画，**没有被补全**）

**质量门禁（`mask_audit`）**

- [ ] `background_residue` 无 `auto` 级条目（有则先修蒙版）
- [ ] `translucent_core` 无 fail（主体不该是半透明的）
- [ ] `edge_contamination` 若 fail/warn → **不得宣称"保真完成"**，只能写"像素未改，边缘存在背景污染"

> 关键区别：**像素未被修改 ≠ 图能用**。像素检查只证明"没被重画"，蒙版质量由 `mask_audit` 负责。两份报告都要看，缺一份就不能下结论。

### 已知不能做的

- 不能把商品重新打光（那会改像素）；
- 不能去掉商品自带的投影（投影随蒙版一起进入，除非逐块手工抠）；
- 不能改名 #D6D6D6 之外的"无缝"质感（纯色就是纯色，不是影棚布）；
- 不能修掉蒙版错误（那是 `mask_repair.py` 的活，且要人工确认）。

## B. Creative Generation

### 使用条件

满足任一条即用：

- 设计还在 `draft`，实物不存在，用户想看"大概长什么样"；
- 需要氛围图、系列合影、灵感板、社媒配图；
- 用户明确说"先看看效果，不用那么准"。

**不满足**：用户已有实物照片且要求"按这个商品出图" → 走 A（只换背景）或 C（重画，须标注）。

### 输入要求

| 必须 | 说明 |
|---|---|
| Design Spec | `design-show` 取回的当前版本；结构、材料、配色必须来自档案，不许凭记忆写 |
| 十段式提示词 | 见 `workflows/image-generation.md` |
| 比例 | 1:1 / 4:5 / 16:9，与投放位置一致 |

可选：氛围参考图（`image1`，仅作风格锚点，不承诺结构一致）。

### 执行流程

1. `design-show` 读档案 → 确认版本与状态（`draft` 也可出图，但要在说明里写清"设计未定稿"）。
2. 写十段式提示词 + 负面词，**从档案字段直接映射**，不要重新创作。
3. 告知额度（每张 5–10 点）→ 用户同意 → 调 1 次。
4. `task-add` → 生成 → `task-done --path <真实路径> --tool ImageGen`。
5. 视觉自检（下面验收标准）→ 把偏差写进 `fidelity_notes`。

### 验收标准

- [ ] 结构：珠数、分段、主石位置与档案一致（±1 可接受，必须记录）
- [ ] 物理：无悬浮、无穿模、无凭空多出的配件
- [ ] 材质逻辑：金属反光方向一致，透明石有透光，珍珠有柔光
- [ ] 画面内无乱码文字、无水印（工具自带水印要裁掉或注明）
- [ ] 比例：主体未被拉伸，链条粗细合理
- [ ] 色彩：**不要求像素等于 HEX**，见 `references/product-consistency.md` 的"三层色差"

B 允许"更好看但不完全一样"，前提是**说明差异**。它不能声称"这就是商品"。

## C. Reference-Based Generation

**这一条路线的名字本身就规定了它的上限：参考，不是复制。**

### 使用条件

必须同时满足：

1. 有实物照片，但**拍摄条件差**（背景脏、光硬、有杂物），需要重打光/换场景；
2. 用户要的是"更好看的展示图"，并接受 AI 模拟标注；
3. 用户**不要求**逐颗珠子、逐个配件、像素级一致。

**不准用的场景**：
- 商品详情页需要"与实物完全一致"的主图 → 只能 A；
- 原图有画外裁切且用户要求"保持裁切关系" → 实际上模型几乎一定补全，慎用。

### 输入要求

| 必须 | 说明 |
|---|---|
| 参考图 | `image1` 商品实拍；复杂结构补 `image2`（侧面/背面）、`image3`（配件特写）。**没有参考图就不算本路线** |
| `input_fidelity` | 调高，靠近原图 |
| Design Spec | 珠数、序列、五金、配色（作为核对基准） |
| 配件清单 | 龙虾扣、延长链、连接环、吊坠固定结构——逐项写"必须有" |
| 画外声明 | 若原图有裁切，明确写"画外保持空白，不得补全"；**并预期它仍可能补全** |

### 执行流程

1. `design-show` → 冻结当前版本作为核对基准。
2. **先定"不可变项"**：珠数、排列、主石固定方式、五金件、金属色。写进提示词句首。
3. 用参考图 + 提示词调用；提示词只做**约束**，不做"从零描述"。
4. 出图后**先跑门禁**，再做视觉复核：
   ```bash
   python3 scripts/fidelity_check.py --config gate.json --json out.json --overlay qa.png --strict
   ```
5. 逐项核对配件可见性（见下）。
6. `task-done` + `fidelity-notes` 写真实差异，不写"基本一致"。
7. **交付时必须标注"AI 模拟展示"**，且不得把它作为"与实物一致"的证据。

### 验收标准

**硬门禁（不过即不可交付）**

- [ ] 背景为无缝纯色且色偏在容差内（`background` 不是 `off_spec` / `lit_backdrop`）
- [ ] 无 `material_mismatch`（色相漂移或饱和度塌陷）
- [ ] 必需配件无 `absent_at_roi`
- [ ] 珠数与排列与 Spec 一致（视觉核对，±1 需记录）
- [ ] 无包边/镶爪/金属笼（若 Spec 未要求）
- [ ] **画外区域没有被补全**（有则记录为保真偏差 → 该图不能作为商品图）

**软门禁（可后期修正，但必须写进报告）**

- [ ] `tone_shift`：色相对但明度偏 → 后期调色可修
- [ ] `inconclusive_low_separation`：主体与背景同色，判色不可靠 → 重打光或换背景
- [ ] `unverifiable_blur`：配件虚化 → 结构无法核对，需补拍或换角度

**标注义务**：C 路线的产物一律写"AI 模拟展示，非实物逐像素还原"。这条不是免责话术，而是因为**它确实做不到**——见 `IMG_2912` 实测：结构越界的补全出现在缩略图上根本看不出来。

## 配件可见性检查（A 与 C 都要做，重点在 C）

首饰的结构信息全在这些小件上，而它们恰好最容易被模型省略、被景深虚化、被画成别的东西。

| 配件 | 为什么必须查 | 查什么 |
|---|---|---|
| 龙虾扣 / 弹簧圈扣 | 决定"能不能戴"，模型常画成磁扣或干脆省略 | 存在、形态对、爪口可动 |
| 延长链 | 决定可调节范围，最常被整段吃掉 | 存在、长度比例、末端尾珠 |
| 连接环 | 承力点，也最容易穿模/融合 | 环与环分明、闭合、无熔接 |
| 吊坠固定结构 | 决定主石会不会掉 | 挂环位置、是否包边/镶爪、有无胶痕 |

分两层查：
1. **代码可查**（`fidelity_check.py`）：该区域有没有前景（`absent_at_roi`）、是否虚到无法核对（`unverifiable_blur`）。
2. **视觉/人工必查**：这个形状**是不是**龙虾扣、环有没有熔成一坨、包边算不算遮住珠面。

代码说"这块区域有个东西且是清晰的"，不等于"这是个龙虾扣"。这个区别不能糊。

## 实测结论（两次真实测试，不是推测）

### Eddy v5（C 路线，1 张 ImageGen）

1. **色号文字压不住像素。** 提示词写 `#F2EFE9 无缝背景`，出来是 `#C9B3A0` 打光布景（ΔE 22.8）；写 `#128D97` 青珠，出来 `#166B6F`（明度差 21）。**HEX 只能当意图，不能当验收标准。**
2. **色差要分层看。** 青珠色相漂移 2.8°、饱和度 −11%、明度 −9 L*：这是"打光偏暗"，不是"拿错石头"。ΔE 一刀切会导出错误的补救动作。
3. **配件会被景深吃掉。** 提示词写了 f/9 全实焦，远侧链节锐度只有参考值的 11–17%，扣件根本没法核对。
4. **主体与背景同色时不能判色。** 珍珠 L 71–75、背景 L 79，ΔE < 10 → 任何"珍珠偏黄"的结论都不可靠。
5. **结构关系要用自然语言分层写。** v4 把珍珠写成串序的一环，模型就画成串珠；v5 改成"链 + 玉髓 = 佩戴主线，珍珠自中央环下垂"，一次就对。

### IMG_2912（C 路线失败 → A 路线成功）

6. **参考图编辑一定会"补全画外"。** 原图手链在左缘、底缘出画，提示词明写"不得补全、保持开口"，生成图仍把它连成完整圆环，并多出 2 颗粉珠、改了扣件与蝴蝶造型。**结论：凡涉及画外缺失，C 路线不可用。**
7. **A 路线做到了 C 做不到的事。** 同一张原图抠图 + `--keep-frame` 合成到 `#D6D6D6`：开口保留、珠数不变、无新增配件、商品不透明度核心区 38 万像素**逐像素 0 差异**、背景实测 `#D6D6D6` 偏差 0。**保真这件事只能靠合成，不能靠生成。**
8. **但 A 路线的瓶颈在蒙版。** 同一张图的蒙版：半透明像素占可见区 23.2%、边缘 75.2% 被判定"更像背景"、4 处待人工确认的残影、alpha 上限 254（永远到不了 255），而且**底缘 3 颗可见珠被整块丢掉**——像素等式检验看不见这件事（那些像素在检查之前就不存在了），是新增的覆盖检查（`pixel_integrity` 的 `coverage`）抓出来的，再用局部二次分割补回。**像素保真通过了，蒙版质量没有通过**——这两句话必须分开说。

## 反模式（明确禁止）

| 做法 | 为什么不行 |
|---|---|
| 把 C 路线产物当商品主图 | 结构可能被改（已实测），属误导 |
| 把 C 路线称作 "strict product fidelity" | 命名就把不可能的能力写成了承诺 |
| 用 B 的产出当商品主图 | 结构与实物无关 |
| 用文字"重绘"已有商品并称其为抠图 | 见 `workflows/background-removal.md` |
| 商品只有局部在画面里却要求"完整商品图" | 只能补拍；补全是编造 |
| 用生成图代替原图做 A 路线输入 | 生成图已重绘，像素保真无从谈起 |
| `pixel_integrity` pass 就说"商品图合格" | 它只证明没被重画，蒙版质量另算 |
| 门禁 `pass` 就说"商品图合格" | 脚本只判可测项；配件身份、珠数仍需视觉/人工 |
| 只出一张图就下"一致性 OK"结论 | 单张无对照，只能核结构，不能核"同一件商品" |
