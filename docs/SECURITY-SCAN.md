# Public Release Security Scan

Scan performed on the development copy at `~/.workbuddy/skills/muselab` and re-run against the
release candidate before packaging. Date: **2026-11-22**.

**Method.** Pattern scan over all text files, plus manual inspection of every non-text artefact
(images) and every path-bearing field. Nothing was deleted from the development copy; the release
candidate was built by an explicit include list and then re-scanned.

**Final pass.** Re-scanned the tree after the last documentation edit and after `git add`: 86 files,
55 of them text (credentials, absolute paths, private IPs, PEM headers — 0 hits), 32 images (no EXIF
at all: no camera, owner, GPS or software tag), no scratch directories, no `__pycache__`, no
`RESULTS.json`, no source photographs. The ignore rules were then confirmed with
`git status --ignored`: nothing left over.

supplied by the host. `scripts/check_env.py` reads capability flags, not keys.

## 2. Local absolute paths

Absolute paths existed in three places in the development copy:

| File | Content | Handling |
|---|---|---|
| `tests/RESULTS.json` | `output_path` values like `/Users/<name>/…/fake_out.png` | **Excluded** — regenerated per run, machine-specific |
| `demo_out/project/project.json` | `workspace_dir` absolute path | **Excluded** — scratch output of `scripts/example.py` |
| `tests/_run/**` (35 run directories) | gate configs, fixture paths, 33 MB | **Excluded** — temporary run scratch |

The release copy of `tests/RESULTS.md` was rewritten to strip absolute paths before packaging
(`<scratch>/…`). Re-scan of the release candidate: **0 hits** for `/Users/` and `/home/`.
