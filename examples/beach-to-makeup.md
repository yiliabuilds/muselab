# 示例：一张海滩照片 → 一套妆容

这条链路和 `examples/beach-to-jewelry.md` 完全同构，只是终点从"能做的首饰"换成"能画在脸上的妆"。所有色值都是实测的，命令都跑过。

## 输入

`images/source_beach.jpg`（1024×1024，手机俯拍海岸）。用户说："根据这张照片设计一套妆容。"

## 第 1 步：真实吸色

```bash
python3 scripts/color_extract.py images/source_beach.jpg --mode mood --max-colors 5 --json palette_mood5.json
python3 scripts/color_extract.py images/source_beach.jpg --mode color --max-colors 7 --json palette_color7.json
```

`extraction_method = pixel_kmeans_lab`，`is_measured = true`。

| 色 | HEX | 面积 | 彩度 | 判读 |
|---|---|---|---|---|
| 灰白 | `#E5E2E0` | 33.1% | 1.4 | 沙滩高亮面，明度 90 → 这是"留白"，不是彩色区 |
| 浅青 | `#66B8BB` | 14.6% | 25.8 | 浅水层 |
| 青 | `#1EA5AC` | 14.4% | 33.8 | 全图最高饱和 |
| 淡灰青 | `#8BB9BC` | 12.1% | 16.0 | 浪花与水的过渡 |
| 深青 | `#0D8D97` | 9.8% | 30.5 | 深水，明度 53 |
| 象牙白 | `#EBF4F7` | 7.3% | 3.4 | 浪脊高光，明度 96 |

气氛：均明度 76.3、均彩度 15.0、冷色占比 1.0、对比跨度 39.6 → **明亮 / 柔和 / 偏冷**。

## 第 2 步：八维分析（只写图里有的）

| 维度 | 观察 |
|---|---|
| Color | 见上表；青只出现在浪脊线附近，且面积越小饱和越高 |
| Shape | 海岸线是一条自左上到右下的连续斜线，只有轻微 S 形；浪脊内侧有细碎的尖角，周期不规则；画面中部有一处小漩涡 |
| Texture | 水：低幅度高频波纹 + 连续镜面高光条；浪花：实心乳白、边缘碎成气泡颗粒；沙滩：均匀哑光细颗粒，无高光 |
| Composition | 对角线分割，水占左下约 55%，沙占右上约 35%，浪脊是接缝；视觉重量在左下 |
| Style | 极简航拍自然摄影，高调、干净 |
| Mood | 均 L 76、均 C 15、冷色 100% → 安静、轻盈、没有攻击性 |
| Symbol | 潮线的往复、退潮后的留白、漩涡作为唯一的"静止点" |
| Design Opportunity | ①把浪脊的斜线做成眼尾走向 ②把水面高光做成眼睑中央一点金属 ③沙面哑光做底妆 ④漩涡做视觉落点 |

## 第 3 步：转译（每条都要能指回证据）

| 参考图 | 落到妆容 | 为什么 |
|---|---|---|
| 灰白 33%、明度 90 | 底妆缎光薄层 | 主色是"留白"，进底妆质感，不进彩色区 |
| 浅青 `#66B8BB` | 眼影主色 `#7FB6B9` | 实测彩度 26 → 压到 22、明度降 3，否则眼皮上发灰 |
| 深青 `#0D8D97` | 眼尾加深 `#14747C` | 取色相、降 10 L*，才读成"线"而不是"阴影" |
| 象牙白 `#EBF4F7` | 眼头哑光提亮 `#E8F1F2` | 参考图高光是镜面连续，不是闪粉 → 用哑光，不用珠光 |
| 浪脊斜线 + 碎边 | 眼线短尾上扬 10°，眼影边界柔化 | 线是斜的但边是碎的，所以做柔边不做硬边 |
| 水的高光条 | 眼睑中央一小块金属 | 只做一次，不重复 |
| 对比跨度 39.6（低） | 修容减淡一级 | 高调图没有深阴影，脸上也不该有 |
| 构图重心在左下 | **不迁移** | 正脸没有等价位置；硬搬会把重点放到下颌，属生造依据 |

最后一行是关键：**搬运不成立时要说出来**，而不是编一个"下方留白=唇部重心"的说法。

## 第 4 步：方案

**潮汐眼 / Tidal Line** · 冷调清透 · 视觉重点：眼（moderate）

- 底妆：中性偏冷缎光，极薄，T 区定妆，保留毛孔
- 眉：自然平眉、灰棕 `#6B625C`，眉头留浅
- 眼影：冷灰米打底 → `#7FB6B9` 至上眼窝 2/3 → `#14747C` 只压眼尾 1/3 与下眼睑后段 → 眼头哑光提亮
- 眼线：0.8mm 深青 `#1B5A61`，只画后 1/3，尾 4mm 抬 10°；内眼线深棕
- 睫毛：纤长型，不贴假睫毛
- 腮红：灰粉 `#B9A3AB` 斜向、边界不可见（**设计补色，不来自色板**）
- 唇：豆沙 `#8A5A5F` 缎面，唇线不外扩
- 修容：极淡冷棕，只在下颌与发际线内侧

克制规则：腮红 shear、唇不加光泽、高光只两点。四区里只有眼是主角。

## 第 5 步：步骤（节选，完整 15 步见档案）

| # | 产品 | 色 | 位置 | 手法 | 效果 |
|---|---|---|---|---|---|
| 6 | 哑光冷灰米眼影 | `#D9D6D3` | 整个眼窝 | 大号刷薄扫一层 | 压住眼皮红调 |
| 7 | 缎光青绿眼影 | `#7FB6B9` | 睫毛根至眼窝 2/3 | 扁刷压色后向上晕，眼尾加宽 | 形成竖向渐变 |
| 8 | 哑光深青 | `#14747C` | 眼尾 1/3、下眼睑后段 | 铅笔刷贴根压，向外晕 2 次 | 拉长眼型 |
| 10 | 深青眼线液 | `#1B5A61` | 上眼睑后 1/3 | 贴根 0.8mm，尾 4mm 抬 10° | 与眼影同色，无黑边 |

## 第 6 步：提示词（六段式的第 3 段最关键）

> 【妆容分区】底妆为中性偏冷缎光薄层，T 区轻定妆；眉为自然平眉、灰棕色、眉头留浅；眼影：冷灰米 #D9D6D3 打底，浅青 #7FB6B9 从睫毛根向上晕至眼窝 2/3，深青 #14747C 只压在眼尾 1/3 与下眼睑后段、范围不超过瞳孔外缘垂直线，眼头与眉骨用哑光 #E8F1F2 小面积提亮、不得有颗粒……

几何锁定句：「眼尾青绿必须止于瞳孔外缘垂直线，不得蔓延到眼窝内侧；腮红与唇色不得抢过眼部。」

## 第 7 步：验收（这一层不能靠嘴）

出图后跑：

```bash
python3 scripts/makeup_check.py --config makeup_gate.json --json gate.json --overlay qa.png
```

它能回答：眼影色相偏了几度、左右眼差多少、皮肤纹理剩几成、唇缘外侧有没有溢色。
它**不能**回答：眼线贴不贴睑缘、有没有多一只眼、还是不是同一个人。

同一个脚本在**错误 ROI** 上的实测（把"眼睛"框到海面上）：

```
eyeshadow_left  -> consistent  (Δhue 9.7°, chroma 1.26)
eyeshadow_right -> consistent  (Δhue 10.1°, chroma 0.98)
```

海水当然"符合"青色设计——因为脚本只做矩形内的色彩算术，不做语义识别。所以 ROI 必须由视觉模型或人给，`consistent` 永远不等于"妆画对了"。

## 第 8 步：局部修订踩到的坑（这段是真跑出来的）

用户接着说："保留原来的底妆和唇妆，只把眼妆改成更日常的版本。" 这一句改动最终走了 9 个版本才干净，每次翻车都是真问题：

| 版本 | 改了什么 | 结果 |
|---|---|---|
| v2 | 只改 `layers.eyeshadow` | 步骤仍写"深青压眼尾" → 档案自相矛盾 |
| v3 | 补发眼妆步骤 | 重发整个列表时漏带"细闪高光"那一条 → **与眼妆无关的步骤被静默删除** |
| v4 | 撤回对唇部步骤的越界改写 | 用户没点名唇，不该动 |
| v5 | 恢复被列表替换清空的色板 | `palette.designed` 从 8 条掉到 1 条才发现 |
| v8 | 补齐色板 + 改写提示词 | 发现 `generation.prompt` 还写着 v1 的 `#14747C` |
| v9/v10 | 补修容步骤、恢复高光原文 | 才算干净 |

出图前跑一次自洽审计，上述问题里有四类能被机器直接抓出来：

```bash
python3 scripts/makeup_spec_audit.py --project <项目> --design mk_beach_tidal --strict
```

它抓到的东西，schema 一条都拦不住：

```
palette_undeclared   #14747C → generation.prompt      色板只申报 6 色，实际用了 9 色
prompt_colour_drift 提示词引用了未申报色值            改了妆没改提示词
layer_without_step  contour                          写了修容做法却没有修容步骤
```

**结论**：schema 保证"格式对"，审计保证"档案里几处说法不打架"。两件事都要做，且审计必须在**出图前**做——否则花额度生成的是旧妆。

## 复用清单

- 吸色：`scripts/color_extract.py`
- 档案与版本：`scripts/muselab_state.py`（`design_category=makeup`，字段进 `module_payload`）
- 出图：`workflows/generation-modes.md` 的 B / C 路线
- 验收：`scripts/makeup_check.py` + 视觉核对 + 人工
- 档案自洽：`scripts/makeup_spec_audit.py`（出图前必跑）

同一张图要三套不同风格，见 `workflows/makeup-design.md` 第 6 步：差异必须在结构（眼结构、质地、唇质地、重心），不能只换颜色。
