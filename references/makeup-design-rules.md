# 妆容设计专业规范

这是 `workflows/makeup-design.md` 的硬约束层。首饰模块的"珠径/五金/负重"在这里对应"妆效层次/显色逻辑/皮肤安全"。**不要把首饰术语搬进妆容**（说"珠光"可以，"珠径"不行）。

## 1. 九个结构层

一套完整妆容按这九层组织。用户只要局部（"只画眼妆"）时，**只输出被要求的层**，其余层写"沿用用户现有妆容"或"未指定"，不得擅自补全成全套。

| 层 | 必须写清 | 不许含糊 |
|---|---|---|
| Base 底妆 | 妆前诉求、粉底质地与色号方向（冷/暖/中性调）、遮瑕范围、是否定妆、最终肤感（哑光/缎光/水光） | "自然底妆"（没有信息量） |
| Brows 眉 | 形状（平/拱/弯）、粗细、眉头浓淡、产品（笔/粉/膏）、是否野生眉处理 | "画个眉" |
| Eyeshadow 眼影 | 打底色／主色／加深色／提亮色各自**落在哪个解剖位置**（眼窝、睑褶内、外眼角 V 区、下眼睑后 1/3、内眼角、眉骨）、边界硬度、晕染范围 | "涂在眼皮上" |
| Eyeliner 眼线 | 线型（内眼线/细线/上扬/下垂/开眼头）、粗细（mm 量级）、眼尾延伸长度与角度、颜色 | "画眼线" |
| Lashes 睫毛 | 夹翘程度、睫毛膏类型（纤长/浓密/卷翘）、是否假睫毛（整条/单簇/下睫毛） | "刷睫毛" |
| Blush 腮红 | 位置（苹果肌/颧骨斜向/横向过鼻梁/眼下方）、形状（圆/斜/横）、质地（粉/膏/液）、浓度 | "打腮红" |
| Lips 唇 | 底色、主色、质地（哑光/缎面/水光/染唇）、唇线处理（是否外扩、扩多少 mm）、是否咬唇 | "涂口红" |
| Highlight / Contour 高光修容 | 按需：修容位置与深度、高光位置与颗粒感（细闪/大闪/无闪） | 不写就说明"本套不做修容"，不要装作做了 |
| Finishing 定妆 | 散粉（区域）或定妆喷雾、最终整体质感、持妆预期 | "定妆"一词不算说明 |

## 2. 视觉重点：一套妆容只能有一个主角

**硬规则**：眼影、腮红、唇、高光四个区域里，最多**一个**处于"高饱和/高强度"，最多**一个**处于"中等"，其余必须克制。

判断"克制"的可操作标准（这是设计约束，不是审美偏好）：

- 主角区：饱和度高、边界明确、面积可辨、有质感对比（如金属/大闪/高光泽）。
- 配角区：与主角**同色系或中性色**，饱和度低于主角约 1/3，边界柔化。
- 若四区都高饱和 → 视觉无重点，且现实中会显脏、显老、上镜发油。这类方案直接判为不合格，不是"风格大胆"。

选择主角的依据必须来自参考图：图的**构图重心**或**最高饱和区域**落在哪，主角就设在哪。参考图没有重心（如均匀渐变）时，由妆容风格决定，并在档案里写明这是设计决定而非图像依据。

## 3. 色彩转译：三层，不许混为一谈

| 层 | 定义 | 来源 | 允许误差 |
|---|---|---|---|
| **① 实测色** | 参考图里真实测到的像素色 | `color_extract.py`，`extraction_method = pixel_kmeans_lab` | 无（这是测量值） |
| **② 设计色** | 妆容**建议使用**的产品色 | 由①按第 3.1 节的偏移规则推导 | 允许与①不同，但必须写明推导理由 |
| **③ 呈现色** | 出图后画面里实际看到的颜色 | 图像生成结果 | 允许与②不同，出图后单独记录偏差 |

**禁止**：把①的 HEX 直接写成②（"眼影用 #69B7BB"），也禁止要求③的像素等于②。

### 3.1 从实测色到设计色的偏移规则

这些是化妆实践中的普遍规律，用于给出**方向与量级**，不是精确公式：

| 转到 | 常见偏移 | 原因 |
|---|---|---|
| 眼影 | 比实测色降饱和 10–25%、明度视肤色上下调 5–15 L\*；蓝绿系在偏黄肤色上需先压一层冷调打底，否则显脏 | 眼皮本身有色素与血管色，粉体叠上去会"变浊" |
| 腮红 | 取辅助色，饱和度再降一档；暖皮偏珊瑚、冷皮偏玫瑰 | 腮红面积大，原饱和度会显得浮 |
| 唇 | 取主色或点缀色的**色相**，明度通常比参考图低 5–20 L\* | 唇部本身偏暗红，浅色唇膏会被唇色拉暗 |
| 眼线/点缀 | 可用参考图里**最高饱和**的色，接近原值 | 细线面积小，高饱和不会压场 |
| 高光 | 取明度最高、彩度最低的色，加冷暖倾向 | 高光是明度游戏，不是色彩游戏 |

若参考图主色是高明度低彩度（如灰白、米白），不要把它当"妆容主色"，它对应的是**底妆质感**或**留白**，主色应取辅助色或点缀色。

## 4. 质感转译：是联想，不是公式

视觉材质 → 妆效质感，可以这样联想（**每一种都只是候选，不是唯一解**，写方案时必须说"因为参考图的 X 特征，我选择 Y 质感"，而不是"海水=珠光"）：

| 参考图质感 | 可对应的妆效 | 落地手法 |
|---|---|---|
| 水面连续高光、镜面反射 | 水光/玻璃唇、湿感眼影 | 唇釉、眼影膏少量点在睑中央，不晕开 |
| 泡沫细密气孔、半透乳白 | 柔焦、细珠光 | 细闪眼影少量压眼窝中央，散粉轻扫 |
| 云层软边、无明确边界 | 全柔边晕染、无眼线或只画内眼线 | 只用哑光，边界用干净刷子扫开 |
| 金属/硬边高光 | 局部金属色眼影、金属眼线 | 金属眼影压在眼尾 1/3 或下眼睑中段，面积控制 |
| 沙面颗粒、均匀无光 | 柔雾底妆、哑光唇 | 哑光粉底 + 薄散粉，唇用哑光唇泥 |
| 粗颗粒、岩石/土壤 | 微颗粒哑光、眉部野生质感 | 眉膏竖刷、避免过度修边 |

**质感必须可执行**：写"细珠光"要能对应到产品类型（细闪眼影/珠光眼影笔）；写"湿润感"要说明是膏体还是唇釉，因为两者的持久度与叠涂方式不同。

## 5. 实际可操作性：硬约束

### 5.1 步骤必须符合真实上妆顺序

标准顺序（质地决定个别调换，调换要说明理由）：

1. 护肤打底 → 2. 妆前（控油/保湿/调色） → 3. 粉底 → 4. 遮瑕 → 5. 局部定妆 → 6. 眉 → 7. 眼影打底 → 8. 眼影 → 9. 眼线 → 10. 睫毛 → 11. 腮红（膏/液状在此，粉状可后移） → 12. 修容高光 → 13. 唇 → 14. 定妆喷雾。

每步必须写：**产品类型 → 颜色 → 位置 → 手法（点/压/晕/拉） → 预期视觉效果**。缺"手法"或"位置"的步骤视为不合格。

### 5.2 不可行的写法（出现即判不合格）

- 把非化妆品材料用于皮肤或眼周（颜料、食用色素、亮片手工片、金属箔、胶水）。
- 眼周使用大于常规眼用规格的粗颗粒亮片，尤其贴近睑缘/内眼角。
- 要求"一次上色即可达到高饱和大面积覆盖"（深色/高饱和色需要叠层与打底）。
- 要求唇形改变超过约 1.5 mm 却只用唇膏（需唇线笔+遮瑕修边，且有过界风险）。
- 把修容写成"改变脸型/瘦脸"（这是光影错觉，不是结构改变，且不得作效果承诺）。
- 承诺持妆时长、不脱妆、不晕染（依皮肤与气候，不能保证）。
- 宣称治疗、修复、美白祛斑、抗敏等医疗或功效（违反广告合规，见 `references/copyright-and-safety.md`）。

### 5.3 肤质与肤色差异

- 同一配色在浅肤色与深肤色上的**显色结果不同**：深肤色需要更高明度或更高饱和才显色，浅色珠光在深肤色上易发灰；浅肤色上高饱和色更"跳"。方案里若用户肤色已知，必须说明调整方向。
- 干皮/油皮影响的是**质地选择与定妆方式**，不是配色。用户没说肤质时，按中性处理并注明"未提供肤质，以下按中性偏混干假设"。

## 6. 面部照片的处理伦理（场景 B）

允许从照片观察：面部轮廓走向、可见肤色（在已知光源下）、现有妆容痕迹、眉眼形状、五官比例关系。

**不允许**从照片推断：

- 真实肤质（干/油/敏感）、过敏史、皮肤病史；
- 年龄、体重、健康状况；
- "你适合什么"这类需要专业面诊的结论。

必须写明：照片受光源、镜头、滤镜影响，肤色判断可能有偏差；如需精确配色，建议在自然光下比对，或到柜台试色。

生成妆容模拟图时：保留可识别的面部特征（脸型、五官比例、眼距、鼻形、肤色基调整体），只改妆容。**改脸不是妆容设计**。

## 7. 质量检查：谁在判

出图后按下表核对。**只有标 code 的能由脚本给出数值**，其余必须视觉模型或人工，报告里分栏写，不许混成一句"已通过"。

| # | 检查项 | 归属 | 说明 |
|---|---|---|---|
| 1 | 眼影颜色是否符合设计方向 | code（需给定 ROI）+ 视觉 | `makeup_check.py` 比色相/饱和度；"这块是不是眼影"仍需视觉 |
| 2 | 左右眼妆是否协调 | code | 左/右眼 ROI 的 ΔE 与 Δhue |
| 3 | 眼线位置与眼部结构是否自然 | 视觉 + 人工 | 需要判断睑缘位置，代码做不到 |
| 4 | 眉毛、睫毛是否畸形 | 视觉 | 结构完整性判断 |
| 5 | 腮红与修容位置是否合理 | 视觉 + 人工 | 需面部解剖参照 |
| 6 | 唇线与真实唇缘是否匹配 | 视觉（+ code 可测"唇缘外溢色"） | 代码只能测边界外侧有没有颜色渗出，不能确认唇形对不对 |
| 7 | 是否出现额外眼睛/睫毛/眉毛/五官 | 视觉 | 计数与形态判断 |
| 8 | 皮肤是否过度磨皮 | code（与参考图对比高频能量）+ 视觉 | 需同一 ROI 的参考图；无参考图时只能视觉判 |
| 9 | 是否擅自改变人物面部特征 | 视觉 + 人工 | **身份保真无法用脚本判定**，必须人看 |
| 10 | 能否用真实化妆方法近似完成 | 人工 | 需化妆经验 |

## 8. 常见不合格方案与改法

| 不合格写法 | 问题 | 改法 |
|---|---|---|
| 荧光绿眼影铺满整个眼窝 | 显肿、显脏，且需极强打底 | 缩小到眼尾 1/3 + 下眼睑后段，其余用同色系低饱和过渡 |
| 全脸高光 + 亮片眼影 + 水光唇 | 四区抢焦点，上镜油光 | 只留一个高光区，唇改缎面 |
| 深唇色 + 重眼影 + 重修容 | 面部重心下坠 | 眼重则唇淡，或反之 |
| 冷灰蓝眼影在暖黄皮上直接叠 | 发灰发脏 | 先冷调打底或改用带绿调的青，降饱和 |
| "自然到看不出来"但要求遮盖所有瑕疵 | 现实中需要厚度，必然有粉感 | 明确取舍：要遮瑕就有粉感，要裸感就接受透出 |
| 眼线拉到太阳穴 | 与眼型不符时显假 | 眼尾延伸一般控制在眼长的 1/5–1/4，按眼型定角度 |

## 9. 与首饰模块的边界

- 首饰讲"结构、五金、负重、可制作性"；妆容讲"层次、显色、质地、可持续性（持妆）"。
- 两者共享的是：实测色板、视觉分析、版本状态机、三条生成路线、AI 标注义务。
- 妆容的"可制作性"= 用市面可买到的化妆品 + 常规手法能完成，不需要特效化妆或定制模具（除非用户明确要做特效妆，那要单独声明超出常规范围）。
